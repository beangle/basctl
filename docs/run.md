# run：嵌入式运行单个 webapp

`basctl run [options] <app> [app args...]` 不读 `conf/server.xml`：把一个 war / Maven
坐标 / http(s) url 写成**单应用 launch spec**，再前台 `jstart run`。它就是 sas 原来的
`launch.sh`，能力并入 basctl 后不再有单独脚本。

```sh
basctl run /path/to/app.war --port=8080 --path=/app
basctl run -Xmx512M org.beangle.ems:beangle-ems-portal:4.8.8 --port=8080
basctl run --engine=undertow http://host/path/app.war --port=9090
basctl run --print /path/to/app.war          # 只写 spec 并打印 jstart 命令，不启动
```

## 参数

| 参数 | 说明 |
|---|---|
| `<app>` | war / 已解压目录 / `g:a:v`（按 `war` 解析）/ http(s) url；参数顺序无关 |
| `--engine=<tomcat\|undertow>` | 嵌入式容器，缺省 `tomcat`（对应 `*-embed` creator） |
| `--base=<dir>` | base 根目录，缺省 `/tmp`；组件目录 = `<base>/<instance>` |
| `--instance=<name>` | 组件目录名，缺省 `sas`；限单个安全路径段 `[A-Za-z0-9._-]` |
| `--workdir=<dir>` | 启动前 `chdir`，缺省当前目录（`sas.sh run` 会传 `$BAS_HOME`） |
| `--spec=<file>` | spec 输出路径，缺省 `<base>/<instance>/run.jstart` |
| `--local=<dir>` / `--remote=<urls>` | jstart 的本地库与上游；缺省取 `M2_REPO` / `M2_REMOTE_REPO`，都没有时用 jstart 默认 |
| `--offline` | 只用本地仓库解析（透传 jstart） |
| `--print` | 只生成 spec 并打印将要执行的 jstart 命令 |
| `-D<k>=<v>`、`-X<opt>` | JVM 参数，进 spec 的 `[runtime]` |
| `--<option>` 及其它非选项 | 应用参数（如 `--port=8080`、`--path=/app`），进 spec 的 `[args]`，由 creator 消费 |

组件目录缺省是 `/tmp/sas`（`--base=/tmp` + `--instance=sas`），与原 `launch.sh` 的
`bas_launch_home` 缺省一致。

## 流程

1. **写 spec**：`<base>/<instance>/run.jstart`，`[app] entry` 是目标，`[engine] init` 写成本
   basctl 的 `make <tomcat|undertow>-embed` 命令行，`[engine]` 其余行是引擎与容器 jar；
2. **前台 `jstart run <spec>`**：jstart 先跑 `[engine] init`（即 `basctl make *-embed`）
   准备容器环境并写出最终启动命令，随后 exec 它（进程变为容器）；basctl 等待其退出并
   返回同一退出码，输出与信号都直通终端。

## 生成的 spec

```ini
# Generated by basctl. Do not edit.

[app]
entry = /path/app.war
base = /tmp
instance = sas
working_dir = /opt/sas

[engine]
init = 'basctl' make tomcat-embed
org.beangle.sas:beangle-sas-engine:0.13.16
org.scala-lang:scala-library:3.9.0
org.scala-lang:scala3-library_3:3.9.0
org.beangle.commons:beangle-commons:6.3.7
org.slf4j:slf4j-api:2.0.19
org.slf4j:jul-to-slf4j:2.0.19
ch.qos.logback:logback-core:1.6.3
ch.qos.logback:logback-classic:1.6.3
org.apache.tomcat.embed:tomcat-embed-core:11.0.26
org.apache.tomcat.embed:tomcat-embed-websocket:11.0.26

[runtime]
-Xmx512M

[args]
--port=8080
--path=/app
```

- `[engine]` **不解析传递依赖**，所以引擎、scala/日志与容器 jar 必须写全；`undertow` 的完整
  集合见 `src/bas/embed.d` 的 `undertowDeps`；
- 嵌入式模式用普通 slf4j + logback（**不带** `beangle-sas-juli`），见 sas 的
  [docs/juli.md](https://github.com/beangle/sas/blob/main/docs/juli.md) §3.4。

## 版本覆盖

`run` 没有 `server.xml` 可依据，引擎与容器版本内置在 basctl（见 `EmbedVersions`），逐项可用
环境变量覆盖：

| 构件 | 环境变量 |
|---|---|
| `beangle-sas-engine` | `bas_engine_version` |
| `scala-library` / `scala3-library_3` | `bas_scala_version` |
| `beangle-commons` | `bas_commons_version` |
| `slf4j-api` / `jul-to-slf4j` | `bas_slf4j_version` |
| `logback-core` / `logback-classic` | `bas_logback_version` |
| `tomcat-embed-*` | `bas_tomcat_version` |
| `undertow-core` | `bas_undertow_version` |
| `undertow-servlet` / `undertow-websockets` | `bas_undertow_ee_version` |

## 与 start 的分工

| 命令 | 输入 | 形态 | 应用数 |
|---|---|---|---|
| `start [server.xml] <farm\|server\|all>` | `conf/server.xml` | 后台（`nohup`），一实例一 JVM | 一个 server 下多 webapp（`[subapp]`） |
| `run <app>` | 命令行 | 前台（等待退出） | 单 webapp（`[app] entry`） |
